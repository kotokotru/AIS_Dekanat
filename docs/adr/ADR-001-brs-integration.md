# ADR-001: Событийная интеграция с БРС через RabbitMQ и Transactional Outbox

- **Статус:** Принято
- **Дата:** 2026-11-05
- **Модуль:** «Успеваемость и GPA»

## Контекст и проблема

Оценки выставляются преподавателями во внешней БРС. Деканату нужен актуальный средний балл (GPA):
по нему формируются рейтинги и приказы о назначении стипендии. В сессию изменения оценок идут
сотнями в минуту, а БРС периодически недоступна. При прямой синхронной передаче часть изменений
теряется при сбоях, GPA считается по неполным данным, и студент может не получить стипендию.

## Принятое решение

- БРС публикует событие `GradeChanged` в очередь RabbitMQ.
- Модуль «Успеваемость и GPA» принимает событие, сохраняет оценку и в той же транзакции
  записывает событие `GpaRecalculated` в таблицу Outbox.
- Фоновый обработчик публикует события из Outbox для модуля «Стипендии».
- Обработка идемпотентна по идентификатору события: повторная доставка не искажает расчёт.
- Сообщения, которые не удалось обработать, попадают в очередь недоставленных (DLQ).

## Отклонённые альтернативы

1. **Опрос БРС по REST по расписанию** — GPA обновляется с задержкой до следующего опроса,
   растёт нагрузка на БРС, изменения между опросами при сбое теряются.
2. **Apache Kafka** — избыточна для объёма одного вуза, требует отдельного кластера и
   сопровождения; гарантий RabbitMQ с подтверждениями и Outbox достаточно.

## Последствия

- Расчёт GPA устойчив к недоступности БРС, оценки не теряются.
- Появляется новый компонент инфраструктуры (RabbitMQ), его нужно мониторить.
- GPA согласован в конечном счёте (задержка — секунды).
